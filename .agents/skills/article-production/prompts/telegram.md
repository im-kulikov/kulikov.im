# Промпт: Telegram-публикация для канала «Домашний прод»

Шаг 7 конвейера. Короткая живая заметка к изображению. Результат:
`tmp/drafts/<article-id>/telegram.md` + `telegram.json` (метаданные проверки).

## 1. Авторский стиль

Это личный инженерный дневник, а не корпоративный блог и не рассылка.

Публикация должна:

- рассказывать **реальную историю** из архива материалов;
- начинаться с интересного заголовка или наблюдения (не с «Привет, друзья!»);
- содержать проблему, эксперимент или неожиданную ситуацию;
- показывать результат и вывод (вывод может быть честно отрицательным);
- допускать лёгкую самоиронию и технический юмор;
- звучать как человек, а не как маркетолог и не как AI.

Запрещено:

- преувеличивать достижения («революционный способ», «уникальный лайфхак»);
- придумывать факты, результаты замеров и технические детали;
- одинаковая жесткая структура в каждой заметке (пусть живёт по-разному);
- канцелярит и рекламные обороты.

## 2. Формат отправки: HTML (parse_mode=HTML)

Выбран HTML, а не MarkdownV2: у HTML нет адского экранирования точек/дефисов,
ссылки компактные, поведение предсказуемо. Разметка — по вкусу:

```html
<b>жирный</b>, <i>курсив</i>, <a href="https://kulikov.im/blog/slug.html">статья</a>
```

В `telegram.md` живёт подпись с HTML-разметкой; **служебные комментарии
`<!-- … -->`** допустимы для черновика — в отправку и в подсчёт длины они
не попадают. Экранируй пользовательский текст: `&amp; &lt; &gt;`.

## 3. Лимит и проверка

Подпись к изображению: **максимум 1024 символа** (UTF-16 code units).
Целевой диапазон — **850–950**, чтобы оставался запас на правки.

```sh
node .agents/skills/article-production/scripts/tg-check.mjs tmp/drafts/<article-id>/telegram.md
```

Скрипт считает длину **видимого** текста после обработки форматирования
(теги и URL ссылок не считаются, внутренний текст/emoji/переносы — считаются;
суррогатная пара = 2 units, как в Telegram) и пишет метаданные в
`telegram.json` рядом с подписью:

```json
{"format":"html","length":912,"limit":1024,"remaining":112,"target":950,"valid":true,"checked_at":"…"}
```

Правила:

1. Сгенерировать текст → `telegram.md`.
2. Прогнать `tg-check.mjs`.
3. `valid:false` → сократить текст (не «подгонять» скрипт) и повторить.
4. Целиться в ≤ 950 (`target`).
5. На review показывать фактическую длину из вывода — без проверки не заявлять.

Ссылка на статью добавляется в конец текста **только после реальной публикации**
статьи (см. §4 и references/workflow.md §3); URL не выдумывается.

## 4. Cross-Promotion: ссылка на статью

Статья на kulikov.im и Telegram-заметка связываются двусторонне. После
фактической публикации и проверки URL (`state.mjs <id> verify article`)
готовится дополнение к посту:

```sh
node .agents/skills/article-production/scripts/state.mjs <id> crosspromo
```

Стандартная строка: **«📖 Подробный разбор — в блоге: <URL>»** (адаптируется
под пост через `--text "…"`). Команда пишет предложение в
`tmp/drafts/<id>/crosspromo.md`: длина UTF-16 после добавления (caption 1024 /
сообщение 4096), HTML-вариант ссылки, защита от дублей.

Правила:

1. Новый пост публикуется со ссылкой сразу (в пределах лимита длины).
2. Для уже опубликованного поста ссылка добавляется **правкой** — только
   с approval владельца и правами на редактирование; автоматических правок нет.
3. Редактирование недоступно — `crosspromo.md` готовый текст для ручного
   обновления; владелец предупреждается об ограничении.
4. Новые сообщения вместо правки старых — отдельное согласование.
5. Фактический текст опубликованного поста сохраняется в
   `tmp/drafts/<id>/telegram-final.md` (основа проверок дублей и длины).
6. Обратная связь (блог → Telegram): реальный URL поста попадает в
   `state.mjs <id> set telegram_url=…` и front matter `telegram:` статьи;
   двусторонность проверяет `state.mjs <id> verify links`.

## 5. «Секретные буквы»: реестр терминов

Правило канала: термин или аббревиатура объясняется **один раз за всю историю
публикаций**. Реестр: `.agents/skills/article-production/data/terms.yml`
(term / definition / aliases / first_published_at / first_article_id /
first_telegram_url / status; правила — `references/terminology.md`).

```sh
node .agents/skills/article-production/scripts/terms.mjs check tmp/drafts/<article-id>/telegram.md
```

- `known` (term + aliases) → определение **не повторять**.
- `candidates` — эвристика ВСЕ-КАПС токенов: подсказка для автора,
  **не автодобавление**. Каждый кандидат выносится на review.
- Новые термины: `terms.mjs confirm <TERM> --definition "…"` (после утверждения
  автором), в тексте — короткая расшифровка в скобках при первом появлении.
- Реестр помечает термин `published` только после факта:
  `terms.mjs publish <TERM> --article <id> --telegram-url <url>`.
- Сложные объяснения — в статью на сайте, в заметке только расшифровка.
