# Промпт: Article Brief + полноценная Markdown-статья для kulikov.im

Шаги 5–6 конвейера (см. `references/workflow.md`): сначала Article Brief, затем статья.
Вход — проанализированный архив (`tmp/working/<article-id>/`: inventory.md, summary.md,
questions.md). Результат — `tmp/drafts/<article-id>/brief.md` и `article.md`.

**Article Brief обязателен и создаётся ДО статьи**; Image Brief (шаг 8) строится на нём
и на готовой статье, а не на названии ZIP-архива.

## 1. Article Brief (`tmp/drafts/<article-id>/brief.md`)

Шаблон — ровно эти разделы (validate.mjs проверяет их наличие):

```markdown
# Brief: <article-id>

## Тема
Одно-два предложения: о чём материал.

## Контекст
Откуда взялась история: предыстория, окружение, почему вообще стало интересно.

## Ключевые факты
Подтверждённые факты из архива (с указанием источника внутри архива): события,
даты, цитаты, числа. Всё, что не подтверждено, — не факт, а вопрос (см. ограничения).

## Проблема
Что сломалось / что хотелось получить / какая была задача.

## Результат
Чем закончилось (результат может быть честно отрицательным).

## Аудитория
Предполагаемый читатель: уровень, что уже знает, что нужно объяснить.

## Заголовок
Рабочий заголовок статьи (≤ 60 символов).

## Краткое описание
2–3 предложения для description (50–200 символов).

## Визуальные объекты
Объекты и сцены, которые стоит показать на иллюстрациях: техника, инструменты,
окружение, возможные визуальные метафоры. Основа будущего Image Brief.

## Ограничения и неопределённости
Что не подтверждено архивом, что нельзя публиковать (конфиденциальное),
открытые вопросы автору (дублируются в questions.md).
```

## 2. Front matter статьи (обязателен; сверен с шаблонами проекта)

```yaml
---
title: "…"            # ≤ 60 символов; итоговый <title> = title :: Kulikov.im (≤ 70)
description: |        # 50–200 символов, для <meta description> и og:description
  …
keywords: [ … ]       # 3–5 шт., свой список на каждую статью (не фолбэк сайта)
date: 2026-11-11      # дата публикации
tags: []              # 2–4, нижний регистр; на мокапе — чипы без ссылок
draft: true           # снимается только на этапе D отдельным решением
slug: kebab-case-id   # URL: /blog/<slug>.html (uglyURLs проекта)
image: cover.webp     # обложка в том же page bundle (16:9, WebP)
telegram: ""          # URL поста канала. ЗАПОЛНЯЕТСЯ ТОЛЬКО реальной ссылкой
                       # после публикации поста (workflow §3). Не выдумывать.
---
```

Ключ `mock: true` в шаблоне отсутствует: это атрибут демо-статей мокапа
(см. `.agents/docs/conventions.md`), реальная статья его не задаёт —
`validate.mjs` присутствие `mock` проваливает.

Структура файлов: `src/content/blog/<slug>/index.md` + `cover.webp`
(page bundle). Статья — leaf bundle; URL, canonical, og:image, hreflang
генерируются шаблонами проекта автоматически (canonical = Permalink;
EN-версий у блога нет и не создаётся — раздел RU-only).
Обложка — выбранная на review концепция (шаг 9): её `blog-cover.webp`
копируется в бандл как `cover.webp`.

## 3. Структура (гибкая; пустые разделы не создаются)

1. Заголовок (title, в теле не дублируется).
2. Краткое описание — 2–3 предложения.
3. Контекст и мотивация.
4. Исходная проблема.
5. Исследование и диагностика.
6. Рассмотренные варианты (таблица — где уместно).
7. Реализация или эксперимент.
8. Результаты (цифры только из архива).
9. Ограничения и нерешённые вопросы.
10. Выводы.
11. Источники и связанные материалы (https, реальные) — **только внутри
    shortcode** `{{< sources >}}…{{< /sources >}}` (см. §4): секция видима
    читателю на странице, но исключена из внутреннего search index сайта.
12. Обсуждение в Telegram — рендерится шаблоном только при заполненном
    `telegram:`; пустое поле не создаёт пустых ссылок.

`<!--more-->` — после вводного абзаца (excerpt для карточки списка).

## 4. Требования к контенту

- Markdown, совместимый с Goldmark проекта (`unsafe: true`, но сырой HTML —
  только когда markdown не выражает задуманное).
- Блоки кода всегда с языком: ```bash, ```yaml, ```go, ```text.
  Подсветка — Chroma с CSS-классами (light/dark настроены в custom.css).
- Таблицы поддерживаются и стилизованы; длинные скроллятся внутри блока.
- **Mermaid сейчас не поддерживается** сайтом. Диаграммы — текстовые схемы
  в кодовых блоках или изображения. Возможная будущая интеграция без тяжёлого
  клиентского JS: рендер диаграмм в SVG **на этапе подготовки статьи**
  (mermaid-cli локально) и вставка готовым SVG-изображением в page bundle —
  ноль JavaScript на странице. Подключение обсуждается отдельно.
- Техническая точность: только факты из архива; нет данных — «не замерял».
- Никаких вымышленных benchmark'ов, логов, результатов.
- Раздел «Источники» — только shortcode (голый заголовок `## Источники`
  запрещён, validate.mjs это проверяет):

  ```markdown
  {{< sources title="Источники и связанные материалы" >}}
  - [Название источника](https://example.com)
  {{< /sources >}}
  ```

  Shortcode рендерит секцию с маркером `data-search-exclude`: читатель видит
  источники в HTML статьи (и в RSS), а внутренний индекс поиска сайта
  (`/searchindex.json`, шаблон `src/layouts/index.searchindex.json`) секцию
  вырезает — внешние ссылки не индексируются как текст статьи и не становятся
  отдельными записями. Attribution и корректные citations сохраняются.

## 5. Конфиденциальность (обязательный этап перед review)

Исходный архив не изменяется. Публикуемая копия (`tmp/drafts/…`) очищается,
затем проверяется:

```sh
node .agents/skills/article-production/scripts/secrets-check.mjs tmp/drafts/<article-id>/
```

Блокируется (high): ключи/токены (ghp_, AKIA, sk-, xox, glpat-…), пароли,
SSH private keys, URL с кредами, bearer-токены.
Ручной разбор (warn): приватные IP (10/8, 172.16/12, 192.168/16 — в примерах
использовать документационные 192.0.2.x / 198.51.100.x / 203.0.113.x),
session/cookie-параметры, e-mail, внутренние hostnames (.local/.lan/.home).
Одобренные на review находки — в baseline-файл; автоматика не заменяет ручной
разбор. Персональные данные — не публиковать вовсе.

## 6. SEO и метаданные

- Title ≤ 60 симв., description 50–200 и уникален, свои keywords.
- Canonical — из slug, руками не дублировать; og:image — `cover.webp`.
- Обложка ≤ 150 КБ (WebP, 16:9) в фирменном стиле (`prompts/image.md`,
  `references/visual-style.md`); для og:image ориентир ≤ 300 КБ (перекрывается
  лимитом 150 КБ).

## 7. Чек-лист перед review (шаг 11: validate.mjs)

`node .agents/skills/article-production/scripts/validate.mjs <article-id>`
проверяет автоматически: разделы brief.md, обязательные ключи front matter,
`draft: true`, отсутствие `mock`, `telegram: ""`, источники через shortcode
`{{< sources >}}` (голый заголовок `## Источники` проваливает гейт), лимит
Telegram-заметки, разрешённые термины-кандидаты, secrets (high), изображения
(если готовы).

Дополнительно руками:

- [ ] Все блоки кода имеют язык; таблицы корректны.
- [ ] Внешние ссылки — https и реальные.
- [ ] Цифры и факты сверены с архивом (`tmp/working/<article-id>/`).
- [ ] Технические допущения выписаны отдельным списком.
