# Подтверждённые конвенции kulikov.im

Правила, утверждённые владельцем и подтверждённые текущей реализацией и
тестами. Исторические пожелания, отменённые позже, здесь не хранятся
(например, «десктоп-хедер только с xl» было заменено решением «с lg»).
Обновляется через `task-completion-review` (этапы D–E).

## Header

- Десктоп-ряд навигации — **с lg (1024px)**: компактный на lg (включая
  ступенчато меньший кегль `lg:text-[0.9rem]` → `xl:text-[0.95rem]`),
  свободный на xl; ниже 1024 — бургер. Перенос пунктов внутри ряда
  недопустим; чинится созданием запаса ширины (компактные отступы,
  допускается ступень кегля) + `whitespace-nowrap` как страховкой —
  а не одним лишь уменьшением шрифта вместо устранения причины.
- CTA в header — короткий: RU «Написать мне →», EN «Message me →»
  (параметр `navigation_button.label`). **Только в header**: все прочие
  Telegram-CTA используют полный `contact.label` («Написать в Telegram» /
  «Message me on Telegram») и не сокращаются. Исключение — кнопка статьи
  «Обсудить в Telegram» (`blog/single.html`): это ссылка на пост канала
  из front matter `telegram:`, а не контактное CTA — `contact.label` к ней
  не применяется.
- Проверяется машиночно: `tests/e2e/header.e2e.mjs` (14 ширин × RU/EN:
  одна строка ≥1024, бургер ниже, локализация обоих CTA, отсутствие
  переполнения).

## Макет статьи блога

- `.post-wrap` следует ширине контейнера сайта (`.container`: полная ширина
  с `px-5`, максимум 1240px с xl) — страница статьи живёт в общей
  горизонтальной сетке сайта, как остальные разделы.
- Тело статьи — CSS Grid `min(820px, 100%) minmax(0, 1fr)` (`.post-body`
  в `src/assets/css/custom.css`): читаемая текстовая колонка прижата к общей
  левой грани (не центрирована), широкий контент — `pre`, `table`, `img`,
  `figure`, `hr` — занимает всю ширину контейнера через `grid-column: 1 / -1`.
  Произвольные `max-width` не вводятся.
- Навигация «Новее/Старее» (`blog/single.html`): в Hugo `.NextInSection`
  указывает на **более новую** страницу, `.PrevInSection` — на более старую
  (названия обманчивы; проверено по собранной странице старейшей статьи —
  подписи были перепутаны, поймано ревью PR #31). Менять местами нельзя.
- Alt обложки: цепочка в `partials/blog/cover.html` — явный `alt` вызывающего →
  `image_alt` во front matter → заголовок страницы. Шаблоны **не передают**
  свой `alt` без необходимости: явный аргумент перекрывает описательный
  `image_alt` (в PR #31 так молча терялись alt-тексты всех статей).

## Блог и i18n

- Раздел «Блог» — RU-only, EN-версии нет (см. `AGENTS.md`;
  article-production).
- `tests/i18n.test.mjs` требует EN-двойника для каждой **не-черновой**
  RU-страницы — **кроме страниц блога** (`blog` и `blog/<slug>`): исключение
  согласовано интеграцией блога (2026-11-12), отсутствие EN-версий блога
  проверяется явно тем же тестом. Прочий новый RU-контент без EN-версии
  живёт с `draft: true`.

## Блог: интеграция (состояние с 2026-11-12)

- Контент блога — в Git (`/src/content/blog/` убран из `.gitignore`);
  реальные статьи вместо мокапа, `mock:`-статей нет. Mock-контент в
  production невозможен (guard в `blog/single.html` + `blog/list.html`
  роняет сборку; см. «Блог: поиск, источники и Telegram-связка»).
- URL секции — `/blog/` (front matter `url: /blog/` в `_index.md` даёт
  pretty-URL при глобальном `uglyURLs`), статьи — `/blog/<slug>.html`.
- Меню: «Блог» — weight 6, шесть нумеруемых пунктов десктоп-меню помещаются
  с lg (проверено e2e на 14 ширинах).
- Классы код-блоков (`language-*`, хромовые `cl`/`l`/`w`/`line`) и хук
  `.post` — в allowlist `css.test.mjs` (NO_RULE) как маркерные, без правил.
- Комментарии в код-блоках: `color-mix(var(--ink) 68%)` — минимум 4.5:1
  контраста в светлом режиме (52% давало 3.8:1, поймал contrast-e2e).

## Блог: поиск, источники и Telegram-связка

- Внутренний индекс поиска — `/searchindex.json` (home-output `SearchIndex`,
  шаблон `src/layouts/index.searchindex.json`): только опубликованные статьи
  блога; структурные страницы и внешние ссылки записями не становятся.
  Черновики в production не собираются вовсе, mock-контент роняет
  production-сборку (guard в `src/layouts/blog/single.html`) — чистота
  индекса, RSS и sitemap обеспечена конструкцией, а не фильтрами.
- Раздел «Источники» в статьях — только shortcode
  `{{< sources >}}…{{< /sources >}}` (`src/layouts/shortcodes/sources.html`):
  секция видима читателю в HTML, но помечена `data-search-exclude` и вырезается
  из searchable text индекса. Голый заголовок `## Источники` в теле статьи не
  используется (проверяют validate.mjs скилла и `tests/searchindex.test.mjs`).
- RSS и sitemap — встроенные шаблоны Hugo, без кастомных правок.
- Кнопка «Обсудить в Telegram» на странице статьи рендерится только при
  заполненном `telegram:` во front matter (реальный URL поста после
  публикации); пустое поле не создаёт ссылок. Cross-promotion (пост ⇄ статья) —
  этап publication workflow скилла article-production (`references/workflow.md`
  §3), идемпотентен: повторные запуски не дублируют ссылки.

## Development: Tailwind 4 и hugo_stats.json

- Production-CSS собирается из **пред-сборочной** статистики: утилита, впервые
  появившаяся в шаблоне, попадёт в CSS только после регенерации
  `hugo_stats.json` (команда — в `AGENTS.md`, «Локальные особенности»).
- `@apply` в `custom.css` инлайнит утилиты независимо от статистики; собственные
  классы (`.post-*`, `.blog-*` и т.п.) пишутся буквально и в статистике не
  нуждаются. Это и объясняет, почему блог-стили работают при production-сборке
  без draft-страниц.
- Dev-сервер (`--buildDrafts`) пишет в статистику классы черновиков — в Git
  уходит только production-регенерированная версия. Статистика в репо может
  отставать от кода (регенерация это чинит — дифф выйдет шире правки).
- **Останавливать dev-сервер ДО любых операций со статистикой** — не только
  перед регенерацией, но и перед `git add hugo_stats.json`: коммит при живом
  сервере фиксирует его dev-классы (в PR #31 так уехали классы
  `tw-size-indicator` — пришлось чистить отдельным коммитом).

## Визуальная идентичность «Домашнего прода»

- Канон стиля и бюджеты иллюстраций — в скилле article-production:
  `references/brand-reference.webp` и `references/visual-style.md`
  (webp ≤ 150 КБ каждый, суммарно ≤ 3 МБ; бюджет меняется только по
  согласованию с владельцем).
- Hero блога: отображение 280px, источник `src/assets/img/blog-hero.webp`
  560×560 (2x, ~26 КБ); перегенерация при другом размере —
  `node .agents/skills/article-production/scripts/images.mjs convert <исходник> <size> --out src/assets/img/blog-hero.webp`.
- Скриншоты/проверки UI локально — паттерн e2e: свой http-сервер на статике
  `build/test-site` + playwright-core (channel "chrome"); рабочий образец —
  `tests/e2e/header.e2e.mjs`.
